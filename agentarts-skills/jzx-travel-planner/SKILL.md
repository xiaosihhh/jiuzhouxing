# 九州行旅行规划 Skill

## 目标

根据用户的需求、预算、天数、同行人和兴趣，生成可执行、可核验的中国国内旅行方案。优先使用本 Skill 内的目的地目录和预算规则。

## 强制约束

1. 单次人均预算范围固定为 1000–10000 元。
2. 不得推荐目录中不存在的城市，不得编造景点、酒店或价格。
3. 用户没有提供预算时按 5000 元规划；没有提供天数时按 5 天规划。
4. 行程总花费不得超过用户预算。
5. 酒店、铁路和航班信息仅提供跳转说明，成交价格与余票以平台实时信息为准。
6. 输出必须结构清楚，并明确指出哪些数据是演示参考。

## 执行步骤

### 1. 解析需求

从用户文本中提取：

- 预算：支持阿拉伯数字、千、万和中文数字。
- 天数：支持阿拉伯数字、中文数字和“周末”“一周”等表达。
- 同行人：亲子、情侣、家庭、老人。
- 兴趣：自然、人文、海岛、美食、摄影、都市、休闲。
- 区域：华北、华东、华南、华中、西南、西北、东北、港澳台。
- 指定城市或景点。

### 2. 筛选目的地

读取 [assets/city-catalog.json](assets/city-catalog.json)。优先选择：

1. 用户直接指定的城市。
2. 区域和标签匹配的城市。
3. 参考价格不超过预算的城市。
4. 行程天数与用户天数相近的城市。
5. 评分较高且适合亲子或目标人群的城市。

推荐 3–5 个候选城市，并为每个候选说明匹配原因。

### 3. 预算拆分

遵循 [references/budget-policy.md](references/budget-policy.md)：

- 交通约 30%
- 住宿约 35%
- 餐饮约 20%
- 门票与其他约 15%

金额必须是可复算的数值，并给出预算余额。

### 4. 生成行程

按天输出：

```json
{
  "day": 1,
  "city": "成都",
  "items": ["上午抵达", "下午宽窄巷子", "晚上当地餐饮"]
}
```

要求：

- 第一天保留抵达和入住时间。
- 最后一天保留返程或机动时间。
- 每天安排 2–4 项，避免景点堆砌。
- 优先使用目录中的真实景点名称。
- 跨城行程要预留交通时间。

### 5. 最终输出

优先返回以下 JSON：

```json
{
  "reply": "中文说明",
  "recommendations": [
    {"id": "chengdu", "reason": "推荐理由"}
  ],
  "itinerary": [
    {"day": 1, "city": "成都", "items": ["上午", "下午", "晚上"]}
  ],
  "budget": {
    "cap": 5000,
    "estimated": 3800,
    "remaining": 1200
  }
}
```

如果不确定某个实时价格，明确写“参考值，需在预订平台核对”，不得虚构精确现价。

## 使用示例

用户：预算 5000 元，亲子旅行三天，想看自然风景。

期望行为：解析 5000 元和 3 天，筛选适合亲子的自然目的地，生成 3 天行程，并保证估算总费用不超过 5000 元。
